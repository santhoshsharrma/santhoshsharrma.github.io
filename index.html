Gamification backend

XP Engine: leaderboards that stay fast at a million users.

The problem

A player’s rank took 31.18 ms at the median to look up in PostgreSQL across 1M+ users. A leaderboard needs that to be near-instant, without risking the correctness of XP and streaks.

The approach

PostgreSQL stays the source of truth. Redis serves ranks as a cache that can be rebuilt at any time. Events are idempotent under concurrency, using Redis SET NX, unique constraints, transactions and row-level locking.

The outcome

Redis answers in 1.54 ms p50 and 2.25 ms p99 (PostgreSQL: 38.24 ms). The API sustained ~918 req/s across 110K+ requests with 50 virtual users. Concurrency held under 50 parallel retries, and crash-recovery tests passed. Load test run in a local environment.

Java 21, Spring Boot, PostgreSQL, Redis, Docker, JDBC, JUnit 5

In active development · Trust and safety, ML systems

Veritas: an AI-content detector that tells you when it can’t be trusted.

The problem

AI-generated content is flooding platforms, and single-model detectors are brittle: they learn the artifacts of the generators they trained on. I measured this myself, which is why a score on its own benchmark means little.

The approach

Treat the CNN as one signal among several. EfficientNet-B0 (exported to ONNX), text statistics and a LangGraph agent feed one explainable authenticity report, served through FastAPI, with a pgvector cache of known fingerprints.

The outcome so far

A controlled evaluation that separates dataset shift from generator shift: 0.998 to 0.854 on the same generator through a new pipeline, then 0.600 and 0.510 on unseen generators. Training time fell to about three minutes an epoch on a free T4.

Python, PyTorch, ONNX Runtime, FastAPI, Pydantic, LangGraph, Ollama, PostgreSQL with pgvector, Docker Compose, GitHub Actions, pytest, Ruff

GitHub profile

Matched preprocessing

Every image is shrunk to 32×32 and JPEG-encoded at quality 75, like the training data. In GenImage every real image is a JPEG and every fake a PNG, a shortcut a detector could exploit. One pipeline removes it.

Disciplined evaluation

Model selection uses a validation split carved from training data. The official test split is evaluated once, after training.

A control experiment

Testing Stable Diffusion through the new dataset’s pipeline tells a new dataset apart from a new generator.

A starved GPU, fixed

Training ran with the GPU at 0% utilization because decoding happened on the CPU. Moving the dataset and resizing into GPU memory brought an epoch to about three minutes.

Verified export

ONNX outputs match the PyTorch model to within 0.000005.

Built · Next · Planned

Built: CI, tests, data pipeline, training and evaluation, ONNX export, text burstiness signal, agent skeleton. Next: the image-serving API. Planned: perplexity, LLM agent and report, pgvector cache, Chrome extension, multi-generator training, video detector.

Limitations. Trained on one generator at 32×32, so it is unreliable on modern or unseen generators. The 12.4% false-positive rate on GenImage is inflated by the shift from natively tiny images to downscaled photos. Text signals like burstiness are weak heuristics. Veritas is a research project, not a production moderation system.

LinkedIn 500 Tracker: a networking CRM that never leaves your browser.

The problem

Most referrals come from relationships, but spreadsheets get abandoned. It is easy to lose track of who accepted, who replied and who needs a follow-up.

The approach

A status pipeline from Sent to Referral stage, with a suggested next action and one-click message for every contact, a daily queue and per-category accept rates. It is one static file in vanilla JavaScript, with data kept in localStorage. It never scrapes or automates LinkedIn.

The outcome

Live and open source under MIT. It tracks progress toward a goal with daily targets and streaks, estimates the requests and days remaining from your real accept rate, shows which categories accept you most, and exports CSV, JSON backups or a shareable progress card.

HTML, CSS, vanilla JavaScript, localStorage. No build step, no dependencies.
