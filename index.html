02 · Gamification backend

XP Engine: leaderboards that stay fast at a million users.

The problem

Looking up a player’s rank took 31.18 ms at the median in PostgreSQL across 1M+ users. A leaderboard needs that near-instant without risking XP and streak correctness.

The approach

PostgreSQL is the source of truth. Redis serves ranks as a cache that can be rebuilt at any time. Events are idempotent under concurrency: Redis SET NX, unique constraints, transactions and row-level locking.

The outcome

Redis answered at 1.54 ms p50. The API sustained ~918 req/s over 110K+ requests with 50 virtual users and 0% HTTP failures. 50 parallel retries and crash-recovery tests held.

In development · Trust and safety

Veritas: an AI-content detector that tells you when it can’t be trusted.






The problem
Single-model detectors learn the artifacts of the generators they trained on. I measured it: a 98.4%-accurate detector fell to chance on a generator it had never seen.


The approach
Treat the CNN as one signal among several, feeding one explainable report.


Done carefully
Matched 32×32 JPEG preprocessing removes the real-JPEG vs fake-PNG shortcut. The test split is evaluated once. A control experiment separates dataset shift from generator shift. GPU starvation fixed, epochs down to about three minutes. ONNX matches PyTorch within 0.000005.


Limitations. One generator, 32×32. Unreliable on modern or unseen generators. The 12.4% false-positive rate on GenImage is inflated by downscaling. Research project, not a moderation system.
